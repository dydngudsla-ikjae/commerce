# 001.member

## 도메인 모델

### members (엔티티)

| 필드               | 타입                                      | 제약                         |
| ---------------- | --------------------------------------- | -------------------------- |
| id               | Long                                    | PK, auto increment         |
| email            | String                                  | unique, not null, 소문자 저장   |
| password         | String                                  | not null, bcrypt 암호화 저장    |
| name             | String                                  | not null, 최대 100자          |
| role             | Enum(CUSTOMER, ADMIN)                   | not null, default CUSTOMER |
| status           | Enum(ACTIVE, INACTIVE, LOCKED, DELETED) | not null, default ACTIVE   |
| login_fail_count | Int                                     | not null, default 0        |
| last_login_at    | LocalDateTime                           | nullable                   |
| created_at       | LocalDateTime                           | not null, default now()    |
| updated_at       | LocalDateTime                           | not null, default now()    |

---

### refresh_tokens (엔티티)

| 필드         | 타입            | 제약                              |
| ---------- | ------------- | ------------------------------- |
| id         | Long          | PK, auto increment              |

## 연관관계

* Member 1:N Order (추후 연동)
* Member 1:1 RefreshToken

---

## 정책

---

### 회원가입 (Sign Up)

* 이메일 + 비밀번호로 회원가입한다.
* 이메일은 unique 해야 한다.
* 이메일은 소문자로 저장한다.
* 비밀번호는 bcrypt로 암호화한다.

---

#### 비밀번호 정책

* 최소 8자 이상
* 영문 대문자, 소문자, 숫자 포함
* 특수문자 포함 (권장)

---

* 기본 role은 CUSTOMER로 설정한다.
* 기본 status는 ACTIVE로 설정한다.

---

### 로그인 (Login)

* 이메일 + 비밀번호로 인증한다.

---

#### 로그인 조건

* 존재하는 사용자
* 비밀번호 일치
* status = ACTIVE

---

#### 로그인 실패 정책

* login_fail_count 증가 (DB 원자 연산)

```sql id="m1h9kq"
UPDATE members 
SET login_fail_count = login_fail_count + 1 
WHERE id = :id
```

* 5회 실패 시 LOCKED 상태 전환

---

#### 로그인 성공 시

* login_fail_count 초기화
* last_login_at 업데이트

---

#### 트랜잭션 정책

* last_login_at 업데이트는 인증 로직과 분리 가능하다.

---

##### 정책

* 로그인 성공 처리(토큰 발급)는 핵심 로직으로 간주한다.
* last_login_at 업데이트는 부가 정보 기록으로 간주한다.

---

##### 처리 방향

* last_login_at 업데이트 실패로 인해 로그인 전체가 실패하지 않도록 한다.
* 필요 시 별도 트랜잭션(REQUIRES_NEW)으로 분리할 수 있다.

---

##### 설계 의도

* 인증 성공을 최우선으로 보장한다.
* 부가적인 DB write 실패가 사용자 경험에 영향을 주지 않도록 한다.

---

#### 인증 성공 처리

* Access Token 발급
* Refresh Token 발급 및 DB 저장

---

### 로그아웃 (Logout)

* Refresh Token 삭제

---

#### 쿠키 정책

```id="o8k1xv"
Path=/api/v1/auth
```

---

#### 정책

* Access Token은 만료 시까지 유효
* Refresh Token 재발급 불가

---

### Access Token 로그아웃 정책

* Access Token은 Stateless 구조

---

#### 정책

* 로그아웃 시 무효화하지 않음
* 만료(30분)까지 유효

---

#### 설계 의도

* Stateless 유지
* 성능 확보
* 짧은 TTL로 보안 보완

---

### 회원 탈퇴 (Withdraw)

---

#### 처리 방식

* 물리 삭제하지 않는다
* status → DELETED

---

#### 트랜잭션 처리

* status 변경
* email 변조
* refresh token 삭제

---

#### 이메일 정책

```id="snr4dz"
user@example.com → user@example.com_deleted_{timestamp}
```

---

#### 정책

* 이메일 재사용 가능
* 기존 주문 데이터 유지

---

#### 비식별 처리

* name → "탈퇴 사용자"

---

### 탈퇴 회원 Access Token 정책

* Access Token은 Stateless 유지

---

#### 정책

* 탈퇴 시 Refresh Token 삭제 → 재발급 차단
* 기존 Access Token → 만료까지 유효
* 이후 자연 소멸

---

## 계정 상태 정책

### 상태 정의

* ACTIVE
* INACTIVE
* LOCKED
* DELETED

---

### 상태 전이

* ACTIVE → LOCKED (5회 실패)
* LOCKED → ACTIVE (관리자)
* ACTIVE → DELETED (탈퇴)
* INACTIVE → ACTIVE (관리자)

---

### LOCKED 해제

* 관리자 수동 해제

---

### INACTIVE 정책

* 관리자 설정
* 장기 미접속 확장 가능

---

## JWT

---

### 토큰 구조

* Access + Refresh
* 1 Member = 1 Refresh Token

---

### Access Token

* 만료: 30분
* Stateless

#### Payload

* sub
* role
* tokenType
* exp

---

### 전달 방식

```id="8pl5tq"
Authorization: Bearer {accessToken}
```

---

### Refresh Token

* 만료: 7일
* DB 저장

---

### 재발급 (Rotation)

* 기존 토큰 폐기
* 새 토큰 발급

---

### 동시성 정책

```id="f2o4h1"
중복 요청:
1번째 성공
2번째 실패 (TOKEN_INVALID)
```

---

### 토큰 만료 흐름

```id="h8u4yz"
Access 만료 → Refresh
Refresh 만료 → 로그인
```
