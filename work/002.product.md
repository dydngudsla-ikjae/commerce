## 정책

---

## 상품 (Product)

* 상품은 사용자에게 노출되는 기본 단위
* 재고 및 가격은 Variant 단위로 관리

---

### 상태

* ON_SALE
* STOPPED

---

### 삭제 정책

* 논리 삭제 (deleted = true)

---

### 노출 정책

* deleted = true → 미노출
* status = STOPPED → 미노출

---

### 상품 상세 조회 정책 (🔥 확정)

* STOPPED / DELETED / 존재하지 않는 상품은 모두 동일하게 처리한다.

---

#### 정책

* 상세 조회 시:

    * 404 PRODUCT_NOT_FOUND 반환

---

#### 설계 의도

* 리소스 존재 여부 노출 방지
* API 응답 일관성 유지

---

## 상품 조회

---

### 목록 조회

* offset pagination (page, size)
* 정렬: created_at DESC

---

### 필터

* category_id
* status = ON_SALE
* deleted = false

---

### 노출 정책

* SOLD_OUT → 노출 (품절 표시)
* STOPPED → 미노출
* deleted → 미노출

---

### 상세 조회

---

#### 포함 정보

* Product
* Options
* Variants

---

#### 응답 구조

```json
{
  "id": 1,
  "name": "티셔츠",
  "options": [
    {
      "name": "COLOR",
      "values": ["BLACK", "WHITE"]
    }
  ],
  "variants": [
    {
      "id": 10,
      "price": 10000,
      "stock": 5,
      "status": "ON_SALE",
      "options": ["BLACK", "M"]
    }
  ]
}
```

---

## 옵션 정책

* 상품 단위 관리
* 옵션명 unique

---

### 예외

| 코드               | HTTP | 설명     |
| ---------------- | ---- | ------ |
| OPTION_DUPLICATE | 409  | 옵션명 중복 |

---

## Variant (SKU)

---

### 역할

* 실제 판매 단위
* 주문 기준

---

### 상태

* ON_SALE
* SOLD_OUT
* STOPPED

---

### 재고 정책

* stock >= 0

---

### 상태 자동 전환 정책 (🔥 확정)

* Variant 상태는 재고 상태에 따라 자동 변경된다.

---

#### 정책

* stock = 0 → SOLD_OUT
* stock > 0 → ON_SALE

---

#### 설계 의도

* 재고와 상태 간 일관성 유지
* 운영 편의성 확보
* 상태 관리 실수 방지

---

### 중복 정책

* 옵션 조합 unique

---

## 재고 동시성 정책 (🔥 핵심)

---

### 방식

```sql
UPDATE product_variants
SET stock = stock - :quantity
WHERE id = :id
AND stock >= :quantity
```

---

### 정책

* 성공 → 재고 차감
* 실패 → 재고 부족

---

### 설계 의도

* DB atomic 처리
* race condition 방지
* 성능 유지

---

## 옵션 구조 변경 정책

* 기존 Variant 유지
* 신규 Variant 생성

---

### 정책

* 주문 이력 존재 → 삭제 불가

## Variant 수정 정책

---

### API 구분

| Endpoint                              | 설명               |
| ------------------------------------- | ---------------- |
| PUT /api/v1/admin/variants/{id}       | price, status 수정 |
| PUT /api/v1/admin/variants/{id}/stock | stock 수정         |

---

### 분리 이유

* stock 변경은 재고 동시성(원자 연산)이 적용되는 영역
* price/status는 일반 수정 영역

---

## 카테고리 정책

---

### 구조

* parent_id 기반 계층 구조 (트리)

---

### 조회 정책

```json
[
  {
    "id": 1,
    "name": "의류",
    "children": [
      {
        "id": 2,
        "name": "티셔츠",
        "children": []
      }
    ]
  }
]
```

---

### 정책

* 상품 생성 시 category 필수

---

### 예외

| 코드                 | HTTP | 설명      |
| ------------------ | ---- | ------- |
| CATEGORY_NOT_FOUND | 404  | 카테고리 없음 |

---

### 카테고리 삭제 정책

* 카테고리 삭제 API는 제공하지 않는다.

---

#### 이유

* 상품과 연결된 상태에서 단순 삭제 불가능
* 참조 무결성 문제 발생

---

#### 설계 의도

* 추후 확장 고려
* soft delete 또는 상품 이동 후 삭제 방식 적용 가능

## 설계 의도

* SKU 기반 구조로 확장성 확보
* 옵션 정규화로 유연성 확보
* 재고 atomic 처리로 동시성 해결
* 논리 삭제로 데이터 정합성 유지
* 가격 스냅샷으로 주문 일관성 유지
